Серверы слушают только 127.0.0.1, доступ из сети не открыт. Локальные cookie разделены по порту. Внешние LLM отключены. Начальные данные ПМ25 требуют сверки групп, а служебные записи — назначения конкретных владельцев.

На текущей машине путь рабочей БД указан в закрытом `private/local-config.json`; он не публикуется. Не открывать одну директорию PGlite одновременно двумя процессами. Для другого компьютера используется SQL-снимок, а не копирование работающего каталога БД.

## Запуск и остановка

Из корня репозитория в PowerShell:

```powershell
& .\scripts\Start-Local.ps1 -Mode work
& .\scripts\Start-Local.ps1 -Mode demo
```

Скрипт проверяет уже работающий сервер, запускает Node скрыто и сохраняет служебный PID/логи в ignored `private/`. Для остановки только своего запущенного процесса:

```powershell
& .\scripts\Stop-Local.ps1 -Mode work
& .\scripts\Stop-Local.ps1 -Mode demo
```

При запрете локальных PowerShell-скриптов можно запустить Node вручную, без изменения политики системы:

```powershell
$env:PORT='3001'
$env:HOST='127.0.0.1'
$env:APP_ORIGIN='http://127.0.0.1:3001'
$env:DATA_DIR='путь к подготовленной рабочей БД'
$env:LLM_PROVIDER='disabled'
node src/server.mjs
```

## Локальный Python

Для проверок без Docker используется Pyodide 314.0.7 (Python/WebAssembly) в отдельном Web Worker. JS, WASM и стандартная библиотека загружаются с локального сервера из установленного пакета, без CDN. Сеть Worker ограничена путём runtime-ресурсов; доступ к API кабинета и внешним адресам блокируется отдельной CSP. DOM и файловая система Windows недоступны; файловая система Python — виртуальная. Лимит учебного вычисления 4 секунды после загрузки runtime, загрузка — до 45 секунд. Жёсткой квоты RAM для браузерного режима нет: не использовать его как защищённый серверный экзаменационный исполнитель.

Пользователь может подделать клиентский результат. Сервер сам сравнивает присланные значения с ожидаемыми, сохраняет происхождение `browser_unverified` и **не выставляет оценку и не повышает компетенцию**. Преподаватель отдельно проверяет код, объяснение и самостоятельность. Собственное решение и полученный эталон/ответ LLM можно проверить на одних тестах. Для официальной серверной проверки подготовлен отдельный Linux Docker runner; его развёртывание и проверка ограничений пока не выполнены.

## Резервная копия и перенос

В кабинете администратора: «Резервные копии» → «Скачать закрытый SQL-снимок». Это согласованный снимок работающей базы без активных сессий. Хранить в закрытой папке и отдельно от единственного диска с БД. Базовый снимок поставки восстановлен в другой локальный PostgreSQL-движок, все 38 таблиц/5 245 строк совпали.

Для командного экспорта рабочий сервер сначала остановить, затем запустить `scripts/export-snapshot.mjs` с тем же DATA_DIR. Для будущего облака: применить миграции в пустой PostgreSQL, восстановить SQL с `ON_ERROR_STOP`, сверить данные, права и сценарии. Детали — DEPLOY_RU.md. Переход в облако начнётся после завершения локальных испытаний и отдельного решения заказчика.
