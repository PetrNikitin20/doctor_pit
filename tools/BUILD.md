# Повторная сборка рукописей

Вычислительные эксперименты запускаются отдельно и не требуют Word или шаблонов. Готовые DOCX находятся в `articles/`.

Для сборки Word установите `requirements-authoring.txt`. Сборка динамической рукописи дополнительно требует `latex2mathml` и файл Microsoft Office `MML2OMML.XSL`; путь задаётся в `research/diff_eq/build_draft.py`. Этот путь зависит от установленной версии Office. Создание рисунков использует Times New Roman из Windows; уже подготовленные рисунки включены в репозиторий.

Исходные журнальные шаблоны не распространяются в этом пакете. Для SITITO поместите предоставленный автору `sitito_template.docx` в `research/article/template-reference.docx` (SHA256 d708cba024080d6422dd81270b88f9eb2a5743a9fa1dc310c8bb49040d1e49b8). Для INJOIT используйте `research/injoit/template-reference.docx`, полученный сохранением предоставленного `.doc` через Word (контрольный SHA256 исходного преобразования 013486ec43ad9fb9ec9461dafb71c9c79dab72e27920cdd6805d4def240d6a73). Повторное преобразование Office может изменить служебные XML, поэтому проверку хеша следует осознанно актуализировать после сверки шаблона. Официальные правила: [SITITO](https://sitito.cs.msu.ru/index.php/SITITO/about/submissions), [INJOIT](https://injoit.org/index.php/j1/about/submissions).

После размещения шаблонов выполните:

```bash
python tools/rebuild_articles.py
```

Сборка сначала сохраняет промежуточные файлы в ignored `work/build`, затем применяет `finalize_manuscript.py` и записывает DOCX в `articles/`. Финализатор обязателен: он сохраняет объекты Word Equation, удаляет заливку таблиц, устанавливает границы ячеек, заменяет длинное тире и задаёт параметры абзацев SITITO из авторского образца. Простого запуска исходного сборщика недостаточно для воспроизведения окончательного оформления.

Для проверки отображения можно применить `tools/render_readonly.ps1 -DocumentPath ... -PdfPath ...` на Windows с установленным Word. Он открывает документ в отдельном скрытом экземпляре только для чтения, экспортирует PDF и не сохраняет DOCX. После любой содержательной правки требуется повторно просмотреть страницы.

`research/diff_eq/build_draft.py` создаёт промежуточный математический текст, из которого `retarget_itvs.py` берёт редактируемые формулы. Это технологический исходник текущей статьи, а не отдельная заявка на публикацию.

Английская версия EJCE собирается отдельно из сохранённой авторской редакции и карты перевода:

```bash
python research/ejce/build_english.py --output articles/Article_EJCE_Interdisciplinary_Learning_Pathways_EN_2026-10-23.docx
python tools/check_ejce_english.py
```

`translation_reference_ru.docx` – собственная авторская рукопись, предоставленная 23 октября, а не издательский шаблон. Её контрольная сумма проверяется перед сборкой; неизвестную редакцию следует сначала изучить. `translation_en.json` содержит перевод абзацев и таблиц, новые ссылки и шифр научной специальности. Два рисунка встроены как SVG с PNG для совместимости; их векторные PDF сохранены рядом. `make_figures_en.py` восстанавливает рисунки по исходному построению и тому же JSON результатов; пути к шрифту и Poppler задаются параметрами. Русские рисунки и вычислительные результаты не перезаписываются.

Полная сборка теперь создаёт пять DOCX для четырёх исследований, включая две языковые версии EJCE. После пересборки требуется заново проверить отображение и обновить контрольные суммы и визуальный аудит.
